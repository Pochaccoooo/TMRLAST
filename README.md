# HR Crew Room

เว็บแอปเครือข่ายภายในของฝ่ายทรัพยากรบุคคล Pattaya Aviation ใช้เฉพาะคนในแผนก
เขียนด้วย HTML, CSS และ JavaScript ล้วน ไม่ใช้เฟรมเวิร์กหรือ build tool

- เว็บไซต์: https://pochaccoooo.github.io/TMRLAST/
- ฐานข้อมูล ระบบสมาชิก และ realtime ใช้ [Supabase](https://supabase.com) (Postgres + Auth + Realtime)
- ถ้ายังไม่ได้ตั้งค่า Supabase ใน `js/config.js` หน้าเว็บจะทำงานในโหมดสาธิตด้วยข้อมูลตัวอย่าง

## ฟีเจอร์

| ส่วน | รายละเอียด |

| ฟีด | โพสต์ 4 ประเภท (แบ่งปันความรู้ ประกาศ ชื่นชม ขอคำแนะนำ) ถูกใจ แสดงความคิดเห็น |
| โปรไฟล์ | ตำแหน่ง ทีม ประสบการณ์ ใบรับรอง ทักษะ และการรับรองทักษะจากเพื่อนร่วมทีม |

## โครงสร้างโปรเจกต์

```
index.html            โครงหน้าเว็บ
css/style.css         สไตล์ทั้งหมด (รองรับธีมสว่าง/มืดตามระบบ)
js/config.js          URL และ anon key ของโปรเจกต์ Supabase
js/app.js             ตรรกะทั้งหมดของแอป (render, ข้อมูล, เข้ารหัส, ปฏิทิน ฯลฯ)
supabase/schema.sql   ตาราง, สิทธิ์ (RLS), trigger และ realtime สำหรับ Supabase
.github/workflows/pages.yml   deploy ขึ้น GitHub Pages อัตโนมัติเมื่อ push
```

ฟอนต์ใช้ Bai Jamjuree, Sarabun และ Chakra Petch จาก Google Fonts

## ติดตั้งครั้งแรก (Supabase)

1. สร้างโปรเจกต์ใหม่ที่ https://supabase.com (แผนฟรีเพียงพอ)
2. เมนู **SQL Editor** → วางเนื้อหาไฟล์ `supabase/schema.sql` ทั้งหมด → **Run**
3. เมนู **Authentication → URL Configuration** → ใส่ Site URL เป็น `https://pochaccoooo.github.io/TMRLAST/`
   (ถ้าอยากให้สมัครแล้วใช้ได้ทันทีโดยไม่ต้องยืนยันอีเมล ปิด "Confirm email" ที่ Authentication → Providers → Email)
4. เมนู **Project Settings → API** → คัดลอก Project URL และ anon public key มาใส่ใน `js/config.js`
5. push ขึ้น GitHub แล้วเปิดเว็บ **สมัครสมาชิกบัญชีแรก** บัญชีแรกจะเป็นผู้ดูแลระบบโดยอัตโนมัติ
   บัญชีถัดไปต้องกรอกข้อมูลพนักงานและรอผู้ดูแลกดอนุมัติในแท็บ "สมาชิก"

## แนวคิดการทำงาน

- หน้าเว็บ render ด้วย JavaScript ล้วนผ่านฟังก์ชัน `h()` สร้าง DOM จาก state กลาง (`state`, `ui`)
- ข้อมูลทุกชนิดเก็บในตาราง `docs` (คอลัมน์ `collection`, `id`, `data` แบบ JSON) แยกเป็นคอลเลกชัน
  `profiles`, `posts`, `opportunities`, `endorsements`, `meetings`, `dm`, `members`, `requests`, `events`
  และ `private` สำหรับข้อมูลส่วนตัวของแต่ละคน (กุญแจเข้ารหัส, ค่าการแจ้งเตือน)
- สิทธิ์อ่าน/เขียนคุมด้วย Row Level Security ในฐานข้อมูล (ดู `can_write` ใน `schema.sql`) ไม่ใช่ที่หน้าเว็บ
- การเปลี่ยนแปลงข้อมูลส่งถึงทุกคนที่เปิดหน้าอยู่ผ่าน Supabase Realtime (`postgres_changes`)
- ห้องประชุมใช้ Realtime channel ต่อการประชุม: presence บอกว่าใครอยู่ในห้อง, broadcast ใช้ส่งแชทและสัญญาณ WebRTC
- ข้อความส่วนตัวเข้ารหัสฝั่งผู้ใช้ (ECDH P-256 + AES-GCM) กุญแจส่วนตัวอยู่ในคอลเลกชัน `private` ที่เจ้าของอ่านได้คนเดียว
- ถ้าไม่ได้ตั้งค่า `js/config.js` ระบบจะเข้าสู่ **โหมดสาธิต**: ใช้ข้อมูลตัวอย่างในหน่วยความจำ (`demoData`) ไม่บันทึก

## การพัฒนา

1. แก้ไขไฟล์ใน `css/` หรือ `js/` แล้วเปิด `index.html` ในเบราว์เซอร์เพื่อดูผล (โหมดสาธิตถ้าไม่มี config)
2. commit และ push ขึ้น `main` เว็บบน GitHub Pages จะอัปเดตเองภายในประมาณ 1 นาที
3. ถ้าแก้โครงสร้างฐานข้อมูล ให้แก้ `supabase/schema.sql` แล้วรันซ้ำใน SQL Editor (ไฟล์เขียนให้รันซ้ำได้)

## ข้อจำกัดที่ทราบ

- การโทรและวิดีโอในห้องประชุมเป็น WebRTC แบบ peer-to-peer ใช้ STUN สาธารณะเท่านั้น ถ้าเครือข่ายของสองฝ่ายอยู่หลัง NAT ที่เข้มงวด (เช่น มือถือคนละเครือข่ายกับออฟฟิศ) สายอาจต่อไม่ติด แก้ได้โดยเพิ่ม TURN server ใน `RTC_CONFIG` ที่ `js/app.js` (เช่นบริการ Metered หรือ coturn ของบริษัท)
- ห้องประชุมยังมีช่องใส่ลิงก์ Google Meet / Zoom / Teams สำหรับกรณีที่ต้องการประชุมหลายคนพร้อมกันจำนวนมาก
- การแจ้งเตือนแสดงเฉพาะขณะเปิดหน้าอยู่ ยังไม่มี push notification
- ตาราง `docs` เหมาะกับข้อมูลระดับแผนก (หลักพันเอกสาร) ถ้าโตกว่านั้นควรแยกตารางและทำดัชนีเพิ่ม
